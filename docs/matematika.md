# Математика решения

Что именно считает каждый алгоритм, почему формула такая, и где у неё границы применимости.
Дополняет [normativy.md](normativy.md), где объясняется банковский смысл показателей.

Все числа получены прогоном на открытом датасете и симуляциями по 20 000 повторов.

---

## 1. Закон Бенфорда

### Откуда берётся формула

Пусть у нас есть величины, охватывающие несколько порядков — суммы кредитов от миллиона до
десяти миллиардов. Ключевое требование к ним — **инвариантность к масштабу**: распределение первых
цифр не должно меняться от того, считаем мы в сумах или в долларах.

Единственное распределение, обладающее этим свойством, — равномерное распределение мантиссы в
логарифмической шкале. Запишем число как `x = m · 10^k`, где мантисса `m ∈ [1, 10)`. Если
`log₁₀ m` равномерно распределён на `[0, 1)`, то

```
P(первая цифра = d) = P( log₁₀ m ∈ [log₁₀ d, log₁₀(d+1)) )
                    = log₁₀(d+1) − log₁₀ d
                    = log₁₀(1 + 1/d)
```

Отсюда падающая кривая:

```
d:      1      2      3      4      5      6      7      8      9
P(d): 0.301  0.176  0.125  0.097  0.079  0.067  0.058  0.051  0.046
```

Единица встречается в шесть с половиной раз чаще девятки. Человек, придумывающий числа,
распределяет первые цифры куда ровнее — на этом и держится тест.

**Когда закон не применим.** Если величины ограничены искусственно (ставки 14–34 %) или живут в
пределах одного порядка, инвариантности к масштабу нет и ждать Бенфорда бессмысленно. Поэтому
тест применяется к `summa` и не применяется к `stavka_foiz` или `muddat_oy`.

### Метрика соответствия

```
MAD = (1/9) · Σ | набл(d) − P(d) |        d = 1…9
```

Среднее абсолютное отклонение по девяти корзинам. Интервалы интерпретации — Nigrini (2012):

| MAD | Чтение |
|---|---|
| < 0.006 | близкое соответствие |
| 0.006 – 0.012 | приемлемое |
| 0.012 – 0.015 | на грани |
| > 0.015 | несоответствие |

Результат на данных:

```
Aloqa Bank      MAD 0.05357   n=1936   ← единственный за границей
Asaka Bank      MAD 0.00712   n=1662
остальные 11    MAD ≤ 0.0057
```

## 2. Почему нужен порог по размеру выборки — с числами

Это главный количественный аргумент всего решения, и его стоит уметь показать.

MAD у честного банка не равен нулю: он колеблется просто из-за случайности выборки. Величина этого
шума падает как `1/√n`. Симуляция — 20 000 честных выборок разного размера, каждая строго по
Бенфорду:

| n | медиана MAD | 95-й перцентиль | **доля честных банков с MAD > 0.015** |
|---:|---:|---:|---:|
| 78 | 0.02616 | 0.03937 | **96.2 %** |
| 300 | 0.01329 | 0.02011 | **32.8 %** |
| 500 | 0.01028 | 0.01562 | 7.3 % |
| 1000 | 0.00732 | 0.01110 | 0.1 % |
| 1568 | 0.00582 | 0.00883 | 0.0 % |
| 2544 | 0.00456 | 0.00698 | 0.0 % |

Читается так:

**При n = 78** — столько чисел даёт агрегированный отчёт на банк — честные данные превышают порог
0.015 в **96 случаях из ста**. Тест не просто слаб, он гарантированно обвиняет всех. Именно это и
есть «ловушка» из ТЗ, и вот её точная цена.

**При n = 300** — значении `MIN_SAMPLE` — ложных срабатываний **треть**. То есть сам по себе порог
выборки не делает правило безопасным; он лишь отсекает совсем безнадёжные случаи.

**Правило становится надёжным примерно с n ≈ 1000.** На фактических данных все банки имеют
1568–2544 записи, где ложных срабатываний ноль — поэтому решение работает. Но если на закрытом
датасете попадётся банк с выборкой между 300 и 1000, он может быть обвинён напрасно.

> **Практический вывод.** `MIN_SAMPLE = 300` взят из текста ТЗ, а не выведен из мощности теста.
> Математически безопасная граница для правила «MAD > 0.015» лежит около 1000. Если нужен
> запас — либо поднять `MIN_SAMPLE`, либо переключиться на бутстрап-порог, который подстраивается
> под n автоматически.

### Бутстрап-калибровка

Модуль `benford/calibration.py` делает ровно то, что показано в таблице: генерирует 1000 честных
выборок размера n и берёт 95-й перцентиль MAD.

```
n = 78    →  порог 0.039     (выше порога Нигрини — тест бессилен)
n = 300   →  порог 0.020
n = 500   →  порог 0.0156
n = 1000  →  порог 0.0109
n = 2000  →  порог 0.0077
```

Это статистически честная альтернатива фиксированному порогу. В текущей реализации она считается и
показывается рядом с вердиктом, но решение принимает порог Нигрини — на фактических n оба критерия
дают один и тот же ответ.

## 3. MAD против χ² — уточнение

В `DECISIONS.md` сказано, что χ² при большом n «объявляет значимым любое отклонение». **Это
утверждение неточно, и на защите его лучше не использовать в таком виде.**

Проверка: доля честных выборок, у которых χ² даёт p < 0.05, при разных n:

| n | 78 | 300 | 500 | 1000 | 2000 | 2544 |
|---|---|---|---|---|---|---|
| доля p < 0.05 | 4.9 % | 5.8 % | 6.0 % | 5.0 % | 5.1 % | 5.9 % |

Доля держится около 5 % при любом n — ровно столько, сколько заложено уровнем значимости. Ошибка
первого рода у χ² **не растёт** с выборкой. Растёт **мощность**: тест начинает замечать всё более
мелкие настоящие отклонения. Это не дефект, это тест работает как задумано.

Фактические χ² по чистым банкам подтверждают:

```
Davr Bank       n=2021  χ²= 5.51  p=0.70
Asaka Bank      n=1662  χ²= 8.33  p=0.40
Universal Bank  n=2072  χ²= 5.20  p=0.74
Xalq Banki      n=2132  χ²=12.45  p=0.13
Aloqa Bank      n=1936  χ²=703.9  p=1e-146   ← единственный
```

Ни одного ложного срабатывания. χ² дал бы **тот же ответ**, что и MAD.

**Честная причина выбрать MAD:**

1. Интервалы Нигрини не зависят от n, поэтому число можно показать аудитору как есть — «0.054,
   несоответствие», без оговорок про размер выборки.
2. Это стандарт литературы по forensic accounting, на который можно сослаться.
3. p-value при n в тысячах вырождается в «0.000» и перестаёт различать степени.

Причина **не** в том, что χ² ошибается. Обе метрики согласны, и χ² оставлен в выводе как
независимая сверка.

## 4. Кучность у порога норматива

```
score = доля наблюдений K1 в полосе (предел, предел + 0.005]
срабатывает при score ≥ 0.6 и не менее 4 наблюдений
```

**Нулевая гипотеза.** Если банк не управляет показателем, его K1 колеблется под влиянием множества
независимых причин, и вероятность попасть в конкретную узкую полосу равна доле этой полосы по всему
рынку.

По данным: доля всех 78 наблюдений в полосе (0, 0.005] составляет **0.1923**.

**Вероятность случайно получить 6 из 6** при такой доле:

```
P = 0.1923⁶ = 5.06 · 10⁻⁵
```

Точный биномиальный тест даёт то же: p = 5.06 · 10⁻⁵. То есть примерно один шанс из двадцати тысяч.

Фактические доли:

```
Asaka Bank      1.000   (6 из 6)
Davr Bank       1.000   (6 из 6)
Universal Bank  0.333   (2 из 6)
Sanoat Bank     0.167   (1 из 6)
остальные       0.000
```

Порог 0.6 попадает в пустой промежуток между 1.000 и 0.333.

**Ограничение метода.** Шесть наблюдений — мало. Биномиальная оценка чувствительна к выбору полосы:
она задана константой 0.005, а не выведена из данных. Проверка устойчивости: при ширине полосы
0.005, 0.010, 0.020 и 0.0345 срабатывают ровно те же два банка — то есть результат к этому выбору
нечувствителен, хотя сама константа произвольна.

## 5. Остальные детекторы

### Избыточное округление

```
score = доля значений отчёта, у которых ≥ 6 нулей на конце
срабатывает при score ≥ 0.3
```

Формальной модели здесь нет — это эвристика. Обоснование эмпирическое: у одного банка score = 0.513,
**у всех остальных двенадцати ровно 0.000**. Между ними нет ни одного промежуточного значения, поэтому
конкретный порог в диапазоне 0.01–0.50 роли не играет.

### Сходимость актива

```
score = |jami_aktivlar − Σ статей актива| / |jami_aktivlar|
срабатывает при score > 0.001
```

Это не статистика, а проверка тождества. Порог 0.001 — инженерный допуск на накопление ошибки
округления при сложении чисел с плавающей точкой, а не уровень значимости.

Пример, Kapital Bank, февраль 2026:

```
сумма шести статей актива   72 370 565 714
заявленный итог             73 805 205 472
расхождение                  1 434 639 758   →  score = 0.0194
```

У остальных двенадцати банков score равен нулю точно, не приближённо.

### Разрыв ряда и подъём к отчётной дате

```
рост(i) = |A(i) − A(i−1)| / |A(i−1)|          относительное изменение м/м

discontinuity     score = max по переходам, кроме последнего
window_dressing   score = рост в последнем переходе
оба срабатывают при score > 0.15, нужно ≥ 4 периода
```

Различие между двумя детекторами — **позиционное**: один смотрит на середину ряда, другой на конец.
Это свойство границы данных, а не самого явления. При другой длине отчётного окна метки могут
поменяться местами.

### Равномерность последней цифры

```
χ² = Σ (набл(d) − n/10)² / (n/10)      d = 0…9,  df = 9
срабатывает при p < 0.001
```

У естественных сумм последняя значащая цифра близка к равномерной. Порог значимости 0.001 выбран
строже поправки Бонферрони:

```
α_Бонферрони = 0.05 / 13 банков ≈ 0.0038
α_выбранное  = 0.001                     ← в 3.8 раза строже
```

Разделение на данных: чистые банки дают χ² ≤ 19, помеченные — ≥ 4278.

### Тождество актив = пассив

```
score = |jami_aktivlar − jami_passivlar| / |jami_aktivlar|
срабатывает при score > 0.0001, справочный
```

Та же природа, что у сходимости актива: тождество, а не гипотеза. Допуск на порядок жёстче, потому
что здесь сравниваются два уже агрегированных итога, а не итог с суммой шести слагаемых.

## 6. Составной балл — где математика хромает

```
composite = Σ score сработавших решающих тестов
```

**Проблема: слагаемые несоизмеримы.** У каждого детектора своя шкала и свой естественный диапазон:

| Детектор | Что за величина | Диапазон |
|---|---|---|
| threshold | доля наблюдений | 0…1 |
| rounding | доля значений | 0…1 |
| arithmetic | относительное расхождение | обычно < 0.05 |
| discontinuity / window_dressing | относительный прирост | обычно < 0.25 |

Сложение доли с относительным приростом — операция без физического смысла. Последствие видно в
ранжировании:

```
Davr Bank       composite 1.5128   = 1.0000 (threshold) + 0.5128 (rounding)
Asaka Bank      composite 1.0000   = 1.0000 (threshold)
Hamkor Bank     composite 0.2096   = 0.2096 (discontinuity)
Universal Bank  composite 0.1634   = 0.1634 (window_dressing)
Aloqa Bank      composite 0.0536   = 0.0536 (MAD)
Kapital Bank    composite 0.0194   = 0.0194 (arithmetic)
```

Aloqa Bank стоит на пятом месте с баллом 0.054, хотя его MAD превышает порог в 3.6 раза, а
разрыв с ближайшим чистым банком — семикратный. Это самое сильное отклонение во всём датасете.
А Davr впереди просто потому, что доля естественно доходит до единицы, тогда как MAD физически не
может быть большим числом.

**Что важно понимать.** На состав списка это не влияет: `suspicious` определяется как
`len(reason) > 0`, то есть по факту срабатывания, а не по величине балла. Балл влияет только на
порядок строк.

**Как чинить, если понадобится.** Нормировать каждый score перед сложением — например делить на
порог детектора, тогда каждое слагаемое означает «во сколько раз превышен порог» и становится
сопоставимым:

```
composite = Σ (score_i / threshold_i)
```

При такой нормировке Aloqa (0.0536 / 0.015 = 3.6) поднялся бы выше Universal
(0.1634 / 0.15 = 1.09).

## 7. Сложность

| Этап | Сложность | На фактических данных |
|---|---|---|
| Первая цифра | O(N) | 26 726 операций `log10` |
| Гистограмма и MAD | O(N) + O(1) | 9 корзин |
| Бутстрап-калибровка | O(B·n), B = 1000 | кэшируется по n |
| Детекторы по отчёту | O(строк отчёта) | 1 014 строк |
| Детектор по нормативам | O(78) | — |
| χ² последней цифры | O(N) | — |

Итого линейно по объёму данных. Доминирует не счёт, а чтение xlsx.

## 8. Сводка допущений

| Допущение | Где используется | Насколько прочно |
|---|---|---|
| Суммы кредитов инвариантны к масштабу | тест Бенфорда | прочно: диапазон 10⁶…10¹⁰ |
| n ≥ 300 достаточно для MAD > 0.015 | `sampling.py` | **слабо: FPR 33 % при n = 300** |
| K1 в отсутствие манипуляции разбросан | детектор порога | правдоподобно, но 6 наблюдений — мало |
| Ширина полосы 0.005 | детектор порога | произвольна, но результат к ней нечувствителен |
| Последняя цифра равномерна | детектор последней цифры | прочно для сумм с копейками |
| Тождества баланса выполняются точно | арифметика, баланс | прочно: у чистых банков ровно ноль |
| Позиция скачка определяет его тип | детекторы роста | **слабо: зависит от границы окна** |
| Баллы детекторов складываемы | составной балл | **слабо: разные шкалы** |

Три отмеченных пункта — известные слабые места. Первые два влияют только на закрытый датасет с
другими характеристиками, третий — только на порядок строк, но не на их состав.
