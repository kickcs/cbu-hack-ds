# ТЗ: RegTech — платформа статистического аудита банковской отчётности

> Хакатон: CBU Coding Hackathon 2026. Направление: FinTech.
> Время на реализацию: 4–5 часов. Оценка: 100 баллов (50 код + 50 защита вживую).

## 1. Контекст задачи

Если цифры в отчётности «нарисованы» человеком, они статистически отличаются от чисел, возникших естественным образом (закон Бенфорда). Нужно построить систему аудита, которая прогоняет реестр банковских кредитов через статистические тесты и ранжирует банки по подозрительности.

## 2. Входные данные

Папка с датасетом: `датасеты/b1_regtech/`

| Файл | Содержимое |
|---|---|
| `кредит_реестри.csv` | Основной датасет: 1400–2600 строк кредитных записей на банк |
| `нормативы.csv` | Нормативы К1, LCR, К3 и их пороговые значения |
| `банки.csv` | Список банков |
| `csv/ · xlsx/ · xml/` | Бонус: сырые отчёты в трёх форматах (ingestion) |
| `_ключ_ответа/нарушения.csv` | Только для самопроверки — какой банк, какое нарушение |

Датасет уже дан в готовом каноническом виде (`кредит_реестри.csv`), многоформатный ingestion — бонус, не обязателен для MVP.

На 2-й день жюри проверяет на другом закрытом датасете в том же формате, но с другими значениями — код должен работать не только на образце.

## 3. Объём MVP (обязательно)

1. **Движок статистического аудита** — считает для каждого банка суммарный балл отклонения от закона Бенфорда.
2. **Дашборд аудитора** — таблица банков, отсортированная так, что самые подозрительные — наверху.

## 4. Обязательные алгоритмы

### 4.1 Тест Бенфорда по первой цифре

Для каждого банка взять первую значащую цифру суммы кредита по каждой записи, построить эмпирическое распределение по цифрам 1–9 и сравнить с теоретическим:

```
P(d) = log10(1 + 1/d),  d = 1..9
```

Обработать краевые случаи: нулевые, отрицательные и некорректные значения сумм — отфильтровать или явно залогировать, не включать в расчёт молча.

### 4.2 Метрика соответствия (выбрать одну)

- **MAD** (mean absolute deviation) между эмпирическими и теоретическими долями, с порогами Нигрини (низкое/умеренное/значимое/явное несоответствие для 9 цифр — использовать общепринятые справочные значения, указать источник в `DECISIONS.md`).
- **Хи-квадрат тест** (`scipy.stats.chisquare` или аналог) как альтернатива.

## 5. КРИТИЧЕСКАЯ ЛОВУШКА — проблема малой выборки

Если объединить все показатели банка в один агрегированный отчёт и прогнать тест Бенфорда, на банк получится всего ~78 чисел. При такой маленькой выборке MAD не отличит случайный шум от закономерности, и подозрительными окажутся все банки.

**Требование:** тест обязан проводиться на `кредит_реестри.csv` (1400–2600 строк на банк), и в коде должна быть явная проверка минимального размера выборки:

```python
if n < 300:
    # флаг "insufficient sample" — не считать банк подозрительным на основании этого теста
```

Это не опциональная деталь — без неё решение не засчитывается по сути задачи.

## 6. Бонусные задачи (после MVP, по +1 баллу за штуку)

- Дополнительные тесты: равномерность последней цифры, склонность к округлению, эффект порога (threshold clustering).
- Многоформатный ingestion (XLSX/XML/CSV → каноническая модель).
- Сопоставление названий столбцов синонимов через Левенштейна/триграммы.
- Валидация «актив = пассив», непрерывность показателей между периодами.
- **Бутстрап-калибровка порога** (наше дополнение, рекомендуется): вместо фиксированных порогов Нигрини — сгенерировать N синтетических выборок того же размера n, честно следующих закону Бенфорда, посчитать на них MAD/хи-квадрат, взять 95-й перцентиль как эмпирический порог. Даёт устойчивость к разному размеру выборки и содержательный аргумент в `DECISIONS.md`.
  - Кросс-валидация в этой задаче **не применяется** — это тест согласия (goodness-of-fit) с теоретическим распределением, а не предсказательная модель; CV тут не имеет смысла и не должна использоваться, если только поверх статистики не строится отдельный ML-классификатор (не входит в MVP).

## 7. Требования к данным / БД

- Битемпоральная модель: период отчёта (`период`) и время подачи (`время_приёма`) — раздельные поля.
- Исходный (сырой) файл сохраняется неизменным, если делается бонус по ingestion.

## 8. Формат результирующего файла (важно для автопроверки)

Файл: `результат/подозрительные_банки.csv` (в имени обязательно слово «подозрительные», «нарушение» или «аудит»)

| Столбец | Описание | Обязателен |
|---|---|---|
| `банк` | Название банка (только те, что признаны подозрительными) | да |
| `значение_mad` | Рассчитанное значение MAD или хи-квадрат | нет (бонус) |
| `причина` | Какой тест дал сигнал | нет (бонус) |

В файл попадают только банки, признанные подозрительными — не весь список.

## 9. Архитектура и стек (рекомендация)

- **Язык:** Python + pandas для загрузки и группировки данных.
- **Дашборд:** Streamlit — минимальные усилия, сразу таблица с сортировкой; либо FastAPI + простой HTML-шаблон, если нужен более «продакшн» вид (закладывать больше времени).
- **Запуск:** обернуть в Docker, чтобы работали `docker-compose up` или `make run`.
- **Структура проекта (пример):**
  ```
  /src
    ingest.py        # загрузка кредит_реестри.csv (+ бонус: xlsx/xml/csv ingestion)
    benford.py        # first_digit(), benford_distribution(), benford_mad(), chi_square_test()
    audit.py           # is_sample_sufficient(n), score_bank(), rank_banks()
    bootstrap.py        # (бонус) эмпирическая калибровка порога
    dashboard.py        # Streamlit-приложение
  /tests
    test_benford.py
  /результат
    подозрительные_банки.csv
  README.md
  DECISIONS.md
  docker-compose.yml
  ```

## 10. Порядок реализации (по времени)

1. **0:00–0:30** — group-by по банку, распределение первых цифр.
2. **0:30–2:00** — реализация теста Бенфорда, MAD/хи-квадрат, обязательная проверка `n < 300`.
3. **2:00–3:00** — экспорт в `результат/подозрительные_банки.csv`, Streamlit-таблица (дашборд).
4. **3:00–4:00** — `README.md`, `DECISIONS.md`, минимум 1 автотест.
5. **4:00–5:00** — бонусы: бутстрап-калибровка порога, доп. тесты (равномерность последней цифры и т.д.), если время позволяет.

## 11. Тесты (минимум)

1. На синтетических данных, точно следующих закону Бенфорда — MAD должен быть близок к нулю.
2. На выборке с `n < 300` функция должна возвращать явный флаг «insufficient sample», а не числовое значение MAD.
